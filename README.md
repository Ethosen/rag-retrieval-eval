# rag-retrieval-eval

Which retriever finds the right section of a research paper? This project compares lexical, dense, hybrid and reranked retrieval on the arXiv split of [Open RAG Bench](https://huggingface.co/datasets/vectara/open_ragbench): 1,000 papers cut into 18,840 sections, with 3,045 questions that each point to one gold section. Some of the questions were generated from tables and figures, so the results can be broken down by modality.

Everything runs locally with small open models (a 6 GB GPU is enough, a CPU works but is slow).

## Key findings

| system | nDCG@10 | recall@1 | recall@5 | recall@20 |
|:--|--:|--:|--:|--:|
| BM25 | 0.793 | 0.633 | 0.892 | 0.964 |
| all-MiniLM-L6-v2 | 0.655 | 0.459 | 0.766 | 0.923 |
| bge-small-en-v1.5 | 0.743 | 0.555 | 0.856 | 0.955 |
| e5-small-v2 | 0.729 | 0.539 | 0.851 | 0.949 |
| Hybrid (BM25 + bge-small, RRF) | 0.809 | 0.641 | 0.924 | 0.985 |
| Hybrid + cross-encoder rerank | **0.839** | **0.690** | **0.937** | **0.985** |

1. **BM25 beats every small dense model.** The questions were generated by an LLM from the gold section, and on average 72% of a question's terms appear in that section, which favours exact term matching. Dense models only win on the quarter of questions with the lowest overlap (nDCG@10 0.640 for bge-small vs. 0.590 for BM25). See [results/OVERLAP.md](results/OVERLAP.md).
2. **Hybrid retrieval helps most where it matters.** Fusing BM25 and bge-small with Reciprocal Rank Fusion adds +0.016 nDCG@10 overall and +0.053 on table questions (p < 0.001). It pushes recall@20 to 98.5%, which makes it a good first stage.
3. **Reranking gives the largest gain.** A MiniLM cross-encoder applied to the hybrid top 20 adds +0.030 nDCG@10 (p < 0.001), mostly at rank 1 (+4.9 points). On table questions alone the gain (+0.015) is not significant.
4. **Keeping tables in the text matters.** Inlining tables as markdown, instead of dropping them, improves table questions by +0.024 (BM25) and +0.036 (bge-small) nDCG@10.
5. **Chunk before embedding.** Embedding whole sections (truncated at 512 tokens) instead of 200-word chunks costs bge-small 0.023 nDCG@10 overall and 0.083 on table questions, because tables usually sit beyond the truncation point.
6. **Image questions are the hardest.** Every system scores lowest on questions generated from figures. Only captions are available as text, and a figure's content is invisible to a text retriever.

Full tables (by modality, by question type, confidence intervals, timings): [results/RESULTS.md](results/RESULTS.md).

## Method

- **Unit of retrieval:** sections. Each section is split into 200-word chunks with a 40-word overlap and prefixed with the paper title. A section's score is its best chunk's score (max-pooling).
- **Tables and images:** tables are inlined as markdown where the paper references them. Image placeholders are removed (captions stay, since they are part of the text).
- **BM25:** my own implementation on a sparse term matrix (k1 = 1.2, b = 0.75, light stopword list). It scores the 79k chunks for all 3,045 questions in about 15 seconds.
- **Dense:** `all-MiniLM-L6-v2`, `BAAI/bge-small-en-v1.5` and `intfloat/e5-small-v2` with their recommended query/passage prefixes, normalised embeddings and exact cosine search.
- **Hybrid:** Reciprocal Rank Fusion (k = 60) of the BM25 and bge-small top 100.
- **Rerank:** `cross-encoder/ms-marco-MiniLM-L-6-v2` scores every chunk of the hybrid top 20 sections.
- **Metrics:** recall@{1,5,10,20}, MRR@10, nDCG@10 at section level, plus document-level recall@5. With one relevant section per question, nDCG@10 is 1/log2(rank+1).
- **Significance:** 95% bootstrap intervals over questions, and paired bootstrap tests (2000 resamples) for every comparison.

## Limitations

- The questions are LLM-generated from the gold section, so this benchmark rewards lexical overlap more than real user questions would. The BM25 result should not be read as "BM25 beats dense retrieval" in general.
- Only small models (≤ 33M parameters) were tested so that everything runs on a laptop GPU. Larger embedders would probably close the gap with BM25.
- Each question has exactly one gold section, so a correct answer found in another section counts as a miss.
- Retrieval only: no answer generation or answer grading.

## Reproduce

```bash
pip install -e ".[dev]"
python -m rag_retrieval_eval download            # ~700 MB to ~/.cache/open_ragbench (override with ORB_DATA_DIR)
python -m rag_retrieval_eval run bm25 minilm bge-small e5-small hybrid bm25/no-tables bge-small/no-tables bge-small/whole-section
python -m rag_retrieval_eval run hybrid+rerank
python scripts/overlap_analysis.py
```

Quick smoke test on 300 questions, without writing results: `python -m rag_retrieval_eval run bm25 --limit 300`.

Embeddings are cached in `results/cache/`. On an RTX 2060, the full run takes about an hour, most of it spent embedding and reranking.

```
src/rag_retrieval_eval/
├── data.py         # dataset download, section rendering, chunking
├── retrievers.py   # BM25, dense, RRF hybrid, cross-encoder reranker
├── metrics.py      # ranking metrics and bootstrap tests
├── report.py       # builds results/RESULTS.md
└── __main__.py     # CLI and experiment definitions
scripts/overlap_analysis.py
tests/test_core.py
```

Checks: `ruff check .`, `mypy`, `pytest`.
